# Architecture and decisions

Updated 26 September 2026. This is the durable record of the implementation choices made for the MVP. [Design](Design.md) owns the visual direction, [MVP](MVP.md) owns acceptance scope, and [roadmap](roadmap.md) owns unfinished work.

## System

```text
Svelte shell (Write / Split / Read, focus, review panels)
  ├─ CodeMirror 6: authoritative Markdown text, selection, history, find
  ├─ IndexedDB: active draft, revisions, recovery copies, preferences
  ├─ file adapter: UTF-8 Markdown import and export
  ├─ main-thread Rust/WebAssembly shortcuts: catalog, key resolution, text edits
  ├─ analysis worker → Rust/WebAssembly writer-core
  │    └─ formatting ranges, paragraph ranges, hashtag ranges, counts, safe preview HTML
  └─ service worker: offline app shell and prompted updates
```

There is no server, account, analytics endpoint, or runtime CDN dependency. The web app is a static PWA. The Rust core has no DOM, storage, or network dependencies so a future Apple or terminal client can reuse its semantics.

## Decisions

| Decision | Why | Consequence |
| --- | --- | --- |
| One live CodeMirror instance across modes | Preserve caret, selection, undo, composition, and scroll state | Preview is separate and never rewrites source text. |
| Rust `pulldown-cmark` in a worker | One Markdown interpretation without blocking input | Analysis carries document ID and revision; stale results are discarded. The `==…==` highlight extension is recognized only inside parser text events, so code, links, and block syntax keep parser-defined behavior. |
| UTF-16 ranges at the worker boundary | CodeMirror uses UTF-16 positions | Rust converts byte ranges once and tests Unicode boundaries. |
| Serialized IndexedDB saves with revision checks | Prevent stale tabs from overwriting newer text | Conflicts become recovery copies; the UI reports save failures. |
| One active draft plus bounded recovery | Keep capture simple and safe | A document library and linked tag index require a later schema decision. |
| Safe preview generated by Rust | Keep raw HTML and executable URLs out of rendered output | Images are placeholders in the MVP. |
| Prompted service-worker updates | Do not reload an active writing session | Update waits for a committed draft. |
| Separate writing and reading CSS tokens with temporary appearance overrides | Let readers tune article presentation without changing the writing canvas | Presets and per-mode values live only in the current page; generated CSS can be copied into source defaults. |
| Local performance instrumentation | Give real-time feedback during dogfooding | No document content or measurements leave the device. |
| Sentence focus within Rust paragraph ranges | Keep the whole current sentence clear across wrapped rows while separating adjacent headings | CodeMirror maps the last parsed paragraph ranges through edits; a local punctuation scan updates focus immediately without waiting for the worker. |
| Immediate save with a quiet confirmation label | Avoid a flashing footer during fast typing without weakening durability | The label settles after a pause; revision and error checks remain immediate. |
| Rust-owned shortcut catalog and Markdown edits | Keep bindings, help text, and source transformations reusable across clients | Svelte maps command IDs to browser file/view actions; CodeMirror applies Rust UTF-16 edits as undoable transactions. |

## Input, analysis, and tags

The same compiled Rust core is loaded on the main thread for short, synchronous shortcut resolution and text edits, and in the worker for document analysis. The catalog supplies the help modal and recognized bindings. Browser events and file pickers stay in Svelte; CodeMirror remains authoritative for text, selection, search, and undo. Shortcut edits return UTF-16 ranges and are dispatched as CodeMirror transactions. Loading the shortcut module does not gate editor creation or typing.

CodeMirror owns the source. A document transaction queues an IndexedDB save and a worker analysis. The worker coalesces queued edits and returns the latest revision. Decoration updates are delayed during IME composition. Rust parser events supply separate ranges for readable Markdown text and its punctuation markers; the supported inline `==…==` extension adds highlight content and delimiter ranges within ordinary text events. The safe preview maps those pairs to `<mark>`. The editor keeps semantic Markdown decorations separate from focus dimming decorations so an input transaction does not rebuild the whole syntax layer.

Focus mode uses Rust paragraph ranges to keep prose separate from headings and other blocks. CodeMirror maps those ranges through local edits until the next worker result arrives. Within the active paragraph, a small local scanner finds sentence ends at `.`, `!`, or `?` followed by whitespace or the paragraph end; it keeps closing quotes with the punctuation and avoids splitting decimals or URLs. The scanner is a focus interaction, not another Markdown parser. Separate focus decorations dim text before and after the sentence and update immediately while typing, so a sentence can cross visual wraps without an asynchronous flash. A local block bounded by blank lines and headings covers the time before the first Rust result.

`writer-core` has `find_tags`: it detects Unicode letter/number tags at token boundaries in ordinary Markdown text, permits `_` and `-` within names, and treats `/` as the nested-tag separator. It excludes code and URLs. It returns UTF-16 ranges for the full tag path without changing the Markdown source or preview text. The editor renders those ranges with distinct tag colors. The current `Analysis.tags` values are display ranges, not a persistent search index.

A linked tag index is deferred until the document-library model is defined. It should store normalized tag identity, document ID, occurrence/count, and source revision; updates must commit consistently with a saved document and handle rename, import, restore, conflict copies, and deletion. Do not infer a complete index from a stale worker result. The roadmap contains this slice.

## Local persistence and offline behavior

The product rename to Trazo leaves the IndexedDB database key `daymark-writer` intact. Browser storage is bound to the origin and database name; changing that key would hide existing drafts and recovery copies. This is a compatibility identifier, not the displayed product name.

IndexedDB schema v1 stores one active draft, recovery entries, and preferences. A draft records ID, filename, text, newline convention, BOM, revision, saved time, caret, and scroll position. Saves are serialized. `Saved on this device` is shown only after the current revision commits. Import and new-draft actions preserve a recovery copy. Export is a separate `.md` download, not synchronization.

The visible save label waits for a short quiet period after the latest committed edit, so quick transactions do not alternate `Saving…` and `Saved…` on every keystroke. The actual revision check remains immediate; import, new draft, and app update use `persistedRevision` and error/conflict state rather than the delayed label as their safety gate. Save failures and conflicts bypass the delay.

The service worker precaches the app, worker, WASM, fonts, icons, and build metrics JSON. The draft is in IndexedDB, not in the asset cache. Offline support starts after the first successful app installation. The browser's storage is still best-effort unless persistence is granted; Markdown export remains the portable copy.

## Measurements

The Performance panel reads browser performance entries and local timers. Its labels are deliberate:

| Display | Measurement |
| --- | --- |
| TTS | First contentful paint when available; first app frame fallback. |
| TTI · editor | Time from navigation start until the editor has been created and reaches its next frame. This is a local editor-ready estimate, not the legacy Lighthouse TTI calculation. |
| TTFB, LCP, CLS, INP estimate | Browser Performance APIs where supported; unavailable values show a dash. INP is estimated from Event Timing interactions. |
| Frame rate / slow frames | `requestAnimationFrame` cadence while the panel is open; gaps over 50ms count as slow. Background tabs pause the reading. |
| Edit → frame | p95 of the last 100 CodeMirror document updates to the next animation frame. |
| Analysis / local save | p95 of the last 100 worker round trips and IndexedDB commits. |
| Build assets | Raw and gzip byte counts generated by Vite from built JS/CSS/WASM and bundled public fonts/icons. It excludes the service worker, HTML, manifest, HTTP overhead, and actual cache/network behavior. |

The panel is a development aid, not a lab benchmark. Real-device latency and transferred bytes must be measured separately. Sampling is local, with frame polling only while the panel is visible.

A Playwright smoke test runs the production preview in a fresh headless Chrome context on a dedicated localhost port. It enters at least 10,000 words, waits for the committed draft, reloads, types character by character, and reads the same panel metrics. The 26 September screenshot (119 fps, 7/8/11 ms edit/analysis/save p95, 0 slow frames/tasks, 20.85 MiB heap, 68/68/5/84 ms TTS/TTI/TTFB/LCP, 0.043 CLS, 40 ms estimated INP) is recorded as a reference, while fixed regression limits allow for the larger draft and host variation. Frame rate is checked against the browser's measured rAF ceiling. Optional browser APIs are checked only when available. The test also reads the production `build-metrics.json`, checks that per-file totals match its raw and gzip totals, and caps them at 920,000 and 450,000 bytes respectively, about 10% above the 26 September build. The JSON report contains numbers and workload size, never draft content. This test is a smoke gate; the MVP device and transferred-byte budgets still require named hardware measurements.

## Temporary appearance state

The source palette and typography are CSS custom properties in `apps/web/src/style.css`, including the theme-specific caret color and 3px width. The Appearance workbench applies inline custom-property overrides on the document root. Writing and Reading preview values are separate; reading presets update independent body, measure, title, and color tokens. Theme previews also update the root theme attribute without saving a preference. Color controls display the current hex value beside each swatch. A generated CSS block updates as settings change and can be copied into the source stylesheet; the workbench itself cannot write project files. The complete settings object remains available as JSON. Reload or Reset to source clears these experiments. The normal appearance menu can persist a light/dark/system preference; the workbench never writes appearance settings to IndexedDB.
